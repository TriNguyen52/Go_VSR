# Seeded faults and exact replay

M9 adds `internal/campaign` and `cmd/vsr-campaign`. The adapter calls the existing
VSR, client, simulator, and independent checker; it introduces no alternate
consensus implementation or protocol rule. No external services are required.

## Recorded configuration

The versioned JSON header contains the source revision, dirty-worktree flag,
Go toolchain, executable SHA-256, simulator version, initial topology and timer
configuration, four seeds, operation count,
fault deadline, virtual-time limit, and event limit. Keep the executable with the
journal. Rebuilding can produce another executable digest, which replay rejects.
With `go run` or VCS stamping disabled, the CLI reads revision and dirty state
from local Git; it refuses to invent a revision when unavailable. An embedded
build identity refers to build time. The executable digest distinguishes builds
from the same commit with different local changes.

Version `vsr-campaign-1` fixes this initial state and scheduling policy:

- Replica IDs 0, 1, 2; empty volatile state, normal view 0, primary 0.
- One live client, endpoint 3, starting with request number 1, one request at a time.
- A local clock every virtual unit; replica retries after 10 units and client
  retries after 30. The core retains its existing heartbeat and suspicion rules.
- Sequential `Put`, `Add`, and `Get` commands on x, y, z; values from -5 to 5.
- Before healing, packets can drop, duplicate, or arrive after 1–12 units.
  Different delays reorder packets. An isolated replica has both link directions
  blocked. Every 20 units the controller chooses a crash, isolation, or connection
  restoration when the failure budget permits. A stopped replica restarts at the
  next controller event; while one is recovering, no other replica can crash.
- At `-fault-until`, all links reconnect, stopped replicas restart, and newly sent
  packets arrive after exactly one unit. Previously sent packets keep their
  schedule. A nonce stream persists across replacements and never reuses a value.

SplitMix64 is implemented locally with specified arithmetic. A master seed derives
four explicit stream seeds for workload, network, crash/control choices, and
nonces. No global RNG, wall clock, or goroutine scheduling influences the run.
Network draws cannot consume workload or recovery randomness.

## Completion and checking

The default campaign uses 20 operations, fault injection through time 200, a total
time limit of 5,000, and a total dequeued-event limit of 100,000 per seed. The
flags `-operations`, `-fault-until`, `-max-time`, and `-max-events` override them.
Faults can stop while a request is still outstanding; that same request retries.
All declared operations must complete, all three replicas must recover and reach
the final applied position in the same normal view, and equal applied positions
must have equal KV snapshots. The adapter also allows 14 units after healing or
the final response, whichever is later, for earlier delayed packets to arrive.
Periodic clocks remain armed; completion does not mean the event heap is empty.

Every commit, application, selection, and installation effect reaches the
independent checker. It checks committed identity and order, independent application
results, selected history, and preservation of acknowledged history. Client
responses are checked against independently evaluated committed order, including
legitimate delayed replies from an older view. Counter and equal-position
snapshot checks run at delivered transitions. Recovery reconstruction is checked
against retained global history after resetting only that process's local progress.

The journal records workload commands, fault choices, nonces, send/drop/delay/copy
decisions, delivered messages and local timers, and ordered protocol effects.
The simulator digest additionally covers stale canceled timers. Replay consumes
recorded choices instead of generating new ones, checking every observed boundary
and effect in order and then the final result and digest. Truncation, extra events,
modified observations, incompatible versions/builds, and changed results fail.
This is divergence detection, not authentication of untrusted journal files.

## Commands and diagnostics

```powershell
go build -o artifacts/vsr-campaign.exe ./cmd/vsr-campaign
./artifacts/vsr-campaign.exe -seed 7 -out campaign-traces
./artifacts/vsr-campaign.exe -replay campaign-traces/seed-7.json
./artifacts/vsr-campaign.exe -seed 1 -seeds 25 -operations 20 -out campaign-traces

# Deliberately exhaust a budget. This fails and still saves seed-7.json.
./artifacts/vsr-campaign.exe -seed 7 -max-events 3 -out campaign-traces/incomplete
./artifacts/vsr-campaign.exe -replay campaign-traces/incomplete/seed-7.json
```

A selected default seed 7 completes 20 operations in 1,212 events at virtual time
299, with digest
`2888ac6577c3c2cf5a22dc8f1060c205f1baad139a4a775b178ed8dcd434427c`.
Successful replay reports `replay identical`. An incompatible header reports
`replay divergence: incompatible simulator version or build`. A changed boundary
reports its journal entry number, time, and kind. Budget/checker failures report
phase, virtual time, event count, and a replay command; replaying a genuine failure
reproduces the failure and exits unsuccessfully. Journals use one file per seed;
choose another output directory to retain earlier campaigns with the same seeds.

## Regression evidence

```powershell
go test ./... -count=1
go test ./internal/campaign -run '^TestSmallCampaign$' -count=1 -v
go test ./internal/vsr -run '^TestResearchFailureScenarios$' -count=1 -v
go test ./internal/checker -run 'TestRejectInvalidHistory|TestViewCheckerRejectsBadSelectionAndOmission|TestReplyUsesIndependentCommittedOrder' -count=1 -v
```

The declared small campaign is seeds 1–25, 20 operations each. Tests assert
coverage of drops, duplicates, partitions, crashes, restarts, commits, application,
selection, and installation. It checks 500 completed requests across 31,858 events.
That seed count is a useful regression sample, not proof of protocol correctness.

The five research schedules live in `internal/vsr/campaign_scenarios_test.go`:
primary failure before a reply (including the nearby pre-ACK boundary), isolated
primary with delayed traffic, lost replies plus duplicates and gaps, obsolete
recovery traffic across two restarts, and a lagging new primary with a lost first
view-change report. They use protocol predicates, check invariants throughout,
heal, and finish pending work. Handler fixtures supplement them for stale ACKs,
duplicate reports, and last-normal-view selection. Compressed canonical regression
traces in `internal/vsr/testdata/*.trace.gz` are compared byte for byte on each run;
they are distinct from the campaign CLI's versioned JSON journals. Only after
reviewing an intentional scheduling change, regenerate with
`$env:VSR_M9_UPDATE_TRACES='1'` and the scenario test, then unset that variable and
rerun the test. Checker negative tests require conflicting commitment, out-of-order
application, and omission of committed history to fail for their specific reason.

Limits remain three volatile replicas, one surviving client, one outstanding
proposal, and at most one crashed or recovering replica. No durable storage,
concurrent clients, external effects, or real-process transport is added. All
journals are held in memory and execution is bounded for educational campaigns.

## Implementation review

Changed files are `internal/campaign/{record,run,run_test}.go`,
`cmd/vsr-campaign/main.go`, `internal/checker/checker.go`,
`internal/checker/reply_test.go`, `internal/vsr/campaign_scenarios_test.go`, six
compressed regression traces under `internal/vsr/testdata`, `README.md`, this
document, and `.gitignore`. The extra trace covers scenario 1 before ACK delivery.
Existing checker rejection tests are reused. Protocol handlers are unchanged.

Executed validation:

```powershell
go test ./... -count=1
go vet ./...
git -c safe.directory=C:/Users/jacks/Desktop/distributed_system_project diff --check
go build -buildvcs=false -o artifacts/vsr-campaign.exe ./cmd/vsr-campaign
./artifacts/vsr-campaign.exe -seed 7 -out artifacts/m9-selected
./artifacts/vsr-campaign.exe -replay artifacts/m9-selected/seed-7.json
./artifacts/vsr-campaign.exe -seed 1 -seeds 25 -operations 20 -out artifacts/m9-campaign
./artifacts/vsr-campaign.exe -seed 7 -max-events 3 -out artifacts/m9-incomplete
./artifacts/vsr-campaign.exe -replay artifacts/m9-incomplete/seed-7.json
```

The full suite, vet, formatting, and diff checks passed. Go cache permissions
required approved execution outside the sandbox. The build disabled VCS stamping
because this sandbox's Git user differs from the repository owner; the CLI's
local Git fallback recorded the revision and dirty state. All five research
scenarios passed against preserved traces. The 25-seed CLI campaign completed
500 operations in 31,858 events. Seed 7 and its replay matched the digest above.
The three-event run retained a journal, reported `phase=faults time=1 events=3`,
and exited 1; replay reproduced that failure and exit status. A copy of seed 7
with its header version changed to `incompatible-demo` exited 1 with
`replay divergence: incompatible simulator version or build`.

The central invariant remains agreement on committed request identities and
application in committed order. The harness observes every relevant effect and
never gives the checker authority to change replica state. A subtle valid case
is an old-view reply arriving after failover: it is checked against that request's
original committed position, rather than against the current value of its key.
The recovered replica likewise rebuilds cached results without creating another
logical increment. Finite campaigns and bounded drain checks cannot establish
correctness under every possible schedule.
